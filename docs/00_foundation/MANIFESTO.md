# ODYS Manifesto

## 1. Intelligence Should Accumulate

AI와의 상호작용은 매번 처음부터 시작되어서는 안 된다.

좋은 시스템은 사용자의 이전 목표, 결정, 학습, 실패 및 성과를 축적한다.

ODYS는 대화를 소비하지 않는다.

ODYS는 경험을 축적한다.

---

## 2. Context Is Infrastructure

맥락은 부가 기능이 아니다.

사용자가 누구인지, 무엇을 하고 있는지, 왜 그것을 하고 있는지 이해하지 못하는 AI는 장기적인 조력자가 될 수 없다.

ODYS에서 context는 시스템의 핵심 인프라다.

---

## 3. Memory Must Be Useful

모든 것을 기억하는 것이 좋은 기억은 아니다.

ODYS의 Memory는 다음 질문에 답할 수 있어야 한다.

- 이 정보는 앞으로 다시 필요한가?

- 어떤 작업과 연결되는가?

- 얼마나 신뢰할 수 있는가?

- 언제 갱신되어야 하는가?

- 언제 잊어야 하는가?

Memory는 저장 공간이 아니라 의사결정을 돕는 시스템이다.

---

## 4. Agents Need Clear Responsibility

Agent를 많이 만드는 것이 좋은 multi-agent system을 의미하지 않는다.

각 Agent는 명확한 역할, 입력, 출력, 권한 및 책임을 가져야 한다.

불필요한 Agent 분리는 복잡성을 증가시킨다.

ODYS는 책임이 분명할 때만 Agent를 분리한다.

---

## 5. Tools Create Real Capability

언어 모델만으로는 실제 세계에서 충분한 행동을 수행할 수 없다.

ODYS는 Tool을 통해 외부 세계와 연결된다.

Tool은 다음과 같은 능력을 제공할 수 있다.

- 검색

- 데이터 조회

- 파일 처리

- 코드 실행

- 캘린더 관리

- 알림

- API 호출

- 외부 서비스 제어

Agent의 실제 능력은 Tool 사용 능력에서 나온다.

---

## 6. Models Are Replaceable

ODYS는 특정 AI 모델에 종속되지 않는다.

모델은 시스템의 핵심 구성 요소이지만 제품 자체는 아니다.

모델은 비용, 속도, 품질, 작업 특성 및 정책에 따라 교체될 수 있어야 한다.

ODYS의 지속 가능성은 model independence에서 나온다.

---

## 7. Autonomy Must Be Earned

AI에게 처음부터 모든 권한을 주지 않는다.

ODYS의 자율성은 점진적으로 증가한다.

기본 흐름은 다음과 같다.

Observe

→ Suggest

→ Prepare

→ Ask

→ Execute

→ Monitor

위험도가 높아질수록 더 강한 승인과 검증이 필요하다.

---

## 8. Humans Retain Authority

ODYS가 더 많은 작업을 수행하더라도 최종적인 권한은 사용자에게 있다.

중요한 결정, 위험한 행동, 되돌리기 어려운 작업은 인간의 통제 범위 안에 있어야 한다.

ODYS는 사용자의 의사를 추측하여 권한을 확장하지 않는다.

---

## 9. Architecture Should Enable Change

ODYS의 초기 구조는 미래의 모든 요구사항을 예측하려 하지 않는다.

대신 변화하기 쉬운 구조를 만든다.

초기에는 Modular Monolith를 사용하고, 실제 필요가 발생할 때 경계를 분리한다.

복잡성은 필요가 증명된 이후에 도입한다.

---

## 10. Build for Reality

ODYS는 문서 속의 완벽한 시스템보다 실제로 사용되는 시스템을 우선한다.

우리는 다음 사이클을 반복한다.

Build

→ Use

→ Observe

→ Learn

→ Improve

실제 사용에서 가치가 검증되지 않은 기능은 핵심 기능이 아니다.

---

## 11. The User Is the First Customer

ODYS의 첫 고객은 개발자 자신이다.

직접 사용하지 않는 기능을 상상만으로 확장하지 않는다.

실제 문제를 해결하고, 반복적으로 사용하고, 효과를 검증한 뒤 일반화한다.

---

## 12. Build a Product, Not a Demo

ODYS의 목표는 기술 데모를 만드는 것이 아니다.

ODYS는 장기적으로 운영되고 개선되며 사용자에게 실질적인 가치를 제공하는 제품이어야 한다.

따라서 다음을 중요하게 다룬다.

- Reliability

- Security

- Maintainability

- Observability

- Testability

- Portability

- User trust

- Sustainable business

---

## 13. One Core, Many Domains

ODYS의 핵심 지능과 운영 원리는 Core에 둔다.

특정 분야의 전문 기능은 Pack으로 확장한다.

Core는 범용적이어야 한다.

Pack은 전문적이어야 한다.

이 경계를 통해 ODYS는 하나의 개인용 도구에서 범용 플랫폼으로 확장될 수 있다.

---

## 14. The Mission

ODYS의 사명은 단순하다.

> Turn fragmented information, intelligence, tools, and actions into a coherent system that helps people move toward meaningful goals.
